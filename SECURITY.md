# Security Policy

This policy applies to every repository in this organization that does not have its own `SECURITY.md`.

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.

Use GitHub's private vulnerability reporting on the affected repository:

1. Open the repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

If private vulnerability reporting is not available for the repository, write to `security@safe.global`.

Please include as much of the following as you can:

- The affected repository, file, and version or commit.
- A description of the vulnerability and its potential impact.
- Steps to reproduce, or a proof of concept.
- Any required permissions, tools, or configuration.
- Suggested mitigations, if known.
- Whether the vulnerability is already public or being actively exploited.

Never include real private keys, seed phrases, access tokens, personal information, or other production secrets in a report.

## What to Expect

We will acknowledge your report within 3 working days, keep you informed while we investigate, and tell you when the issue is resolved. Please give us a reasonable amount of time to fix the issue before you disclose it publicly.

## Supported Versions

Security fixes are provided for the latest release and the default branch of each repository. Older releases are not supported unless the repository says otherwise.

## Bug Bounty

Safe runs a bug bounty program. See <https://docs.safe.global/advanced/smart-account-bug-bounty> for its scope, rewards and rules.
