# Support

Thank you for using Safe. This page tells you where to take a question so that it reaches the people who can answer it.

> [!WARNING]
> No one from Safe Labs will ever ask for your seed phrase, recovery phrase, or private key, or ask you to sign a transaction, connect your wallet, or install software to "verify", "restore", or "unlock" an account. We never start a support conversation by direct message. Treat unsolicited offers of help as scams.
>
> Safe{Wallet} is self-custodial. Safe Labs cannot reverse a transaction, restore access, or return funds. Treat anyone who offers to do so as a scam.

## Where to Go

| What you need | Where to go |
| --- | --- |
| Help using Safe{Wallet} on web or mobile | [Help Center](https://help.safe.global) |
| Documentation for the SDKs, APIs, and smart account | [docs.safe.global](https://docs.safe.global) |
| A question about building with Safe | [Ethereum Stack Exchange](https://ethereum.stackexchange.com/questions/tagged/safe-core) with the `safe-core` tag |
| A bug in code from this organization | An issue on the affected repository, if issues are enabled there |
| A feature request | An issue on the affected repository, if issues are enabled there |
| A security vulnerability | The [security policy](SECURITY.md). Do not open a public issue. |
| A phishing site or an account impersonating Safe | `security@safe.global`, with the address of the site or account |

## Before You Open an Issue

- Search the existing issues, the documentation, and Stack Exchange. Your question may already be answered.
- Use GitHub issues for bug reports and feature requests. Questions and general support requests may be closed and redirected.
- Open the issue on the repository the problem belongs to. If you are not sure which one, pick the closest and say so.

## What to Include

- What you did, what you expected, and what happened instead.
- The version or commit, the network, and the browser, device, or runtime.
- Steps to reproduce, with error messages and logs.
- Safe addresses and transaction hashes, if they help. Posting them links your GitHub account to that Safe in public, so use a test Safe where you can.

Never post private keys, seed phrases, API keys, or personal data in an issue.

## Response Times

Issues are handled by the team that maintains each repository, on a best-effort basis. We cannot promise a response time on GitHub.
